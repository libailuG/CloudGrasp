# 第 7 课：故障排查与复盘

## 目标

根据证据区分系统未就绪、识别失败、规划失败、执行失败与物体未抓起，练习恢复并复核。

## 实验 1：暂停仿真后的就绪检查

前提：没有抓取正在运行。启动仿真并确认 READY，然后在 Gazebo 点击暂停。等待约 3 秒，让最近一次消息的新鲜度窗口过去，再执行：

```bash
cd /root/gpufree-data/cloudgrasp_ws/src/CloudGrasp
bash cloudgrasp_sim/scripts/ready.sh --timeout 8
```

ready.sh 加载 ROS 环境并运行 preflight.py；只读取状态、查询控制器及动作服务是否可用，不发送运动目标。
--timeout 8 是就绪检查最多等待约 8 秒；使用单调墙钟计时，因此仿真时钟暂停后仍能超时结束。
暂停时可能仍能发现节点、控制器和动作服务，但时钟不推进，关节状态或相机数据可能停止更新。实际缺失项以输出为准，不提前假定所有项都会失败。
若未就绪，预计出现 Waiting for，最终 NOT READY，返回非零退出码。该结果是本次人为暂停实验的预期结果，不表示需要重装 ROS。

恢复：点击 Gazebo 播放，再次执行同一检查，等待 READY。学员反馈之前不勾选完成。

## 排查顺序

1. 系统就绪：ready.sh，时钟、状态、控制器和服务。
2. 感知识别：候选物体数量、坐标系、位置和尺寸。
3. 运动规划：IK 或轨迹规划错误、失败阶段。
4. 执行：控制器响应与执行结果。
5. 物理抓取：PASS/FAIL 与物体位移报告。

## 恢复实验：通过

学员恢复 Gazebo 播放后重新执行检查，输出初始 Waiting for，随后 READY: clock, joints, camera, controllers and actions are available。确认暂停→未就绪→恢复→就绪的完整实验通过。初次等待是新启动的检查程序需要发现服务并接收状态，不代表曾发生永久故障。
下一步口头分析日志情景：READY 后出现 No graspable box found in camera point cloud，应先检查感知候选数量、位置和尺寸，而不是先判断控制器故障。该错误可能代表没有候选满足抓取筛选，不能直接等同于原始点云为空。等待学员判断阶段。

## 感知失败情景复盘：通过

学员正确选择先检查视觉候选的位置和尺寸，并指出机械臂可能遮挡方块。补充：控制器不负责识别，但机械臂姿态、场景、坐标变换及点云中的机器人部件可能间接影响感知，因此不能绝对说两者没有关系。
排查应先查看 inspect_objects.py 的候选数量、frame、位置和尺寸，再与抓取源码的筛选条件比较；随后按证据检查遮挡、点云过滤和 TF。
下一情景：已有 VISION TARGET 日志，随后报 No collision-free IK solution，应定位为逆运动学求解阶段；可能涉及目标可达性、末端姿态、关节限制、模型/TF、碰撞场景或求解时间，不能仅凭这条报错认定目标绝对不可达。等待学员判断是否已进入轨迹执行。

## IK 失败情景复盘：通过

学员正确判断 No collision-free IK solution 发生在逆运动学阶段，没有进入本次目标的轨迹执行。说明仅针对这次目标；完整抓取流程可能在此之前已经张开夹爪或回初始姿态。
下一情景：set_target 成功返回，随后 pregrasp from vision: planning failed after 3 attempts。应定位为轨迹规划阶段，本阶段 group.execute(plan) 不会执行；目标配置满足要求不保证从当前状态能在给定模型、场景和规划预算下找到有效路径。等待学员解释起终点与完整路径的区别。

## 路径规划失败复盘：通过

学员指出目标不同于过程，过程中可能出现问题。理解正确。补充：规划需检查途中的机器人状态是否满足碰撞和运动约束；即便存在可行路径，有限规划时间内也可能未找到，因此 planning failed 不等于物理上绝对无路可走。
下一情景：Planning request complete → Execute request accepted → execution failed。说明规划完成且执行请求被接受，但执行未成功，应先结合失败阶段的控制器日志、关节反馈和 /clock 定位，不凭报错盲目增大速度或重新调视觉筛选参数。accepted 不等于完成，具体原因需证据。等待学员选择优先检查的模块。

## 执行失败情景复盘：通过

学员正确选择优先检查控制器和仿真运行状态。补充：不能绝对说执行失败与视觉结果无关，错误定位可能间接产生不合理目标或影响物理结果，但应以失败阶段的执行日志、关节反馈与时钟为首要证据，而非先盲目修改视觉参数。结合第 5 课物理验证复盘，故障阶段分类验收完成。

最后整体复盘：请学员用自己的话串联相机点云、物体识别与坐标变换、目标选择和预抓取位姿、IK、轨迹规划、控制器执行、Gazebo 接触与物体位移验证。重点说清输入如何变成动作，以及如何判断成功，不必背代码名。等待回答，暂不勾选完整流程复盘。

## 最终整体复盘：通过

学员总结：请求搬运方块；点云判断物体在世界中的位置；将物体位置交给 MoveIt，按先到上方、下降夹取、抬升、转移、下降释放的流程完成任务，中间有各项保护措施。已能串联总体流程。
补充：抓取程序根据视觉目标构造末端目标位姿，通过 IK 求目标关节配置，再由 MoveIt 规划轨迹并协调控制器执行；分阶段的抓取顺序由任务代码编排。动作流程完成后还需用方块实际位移验证成功，不能只根据执行结束判定完成。保护检查包含就绪、候选筛选、IK/规划结果、路径完整性、执行结果和超时等。
