# 机械臂滑条控制面板

源码：`cloudgrasp_lab/scripts/control_panel.py`。
适用于本学习实验的阶段 2 及以上；直接控制关节，不经过 MoveIt 碰撞规划。首次练习优先只动手腕的小角度，避开已有障碍。

## 打开

先启动阶段 2，在另一个项目终端运行：

```bash
bash learning/rebuild/lab.sh panel
```

服务器桌面也有“CloudGrasp 机械臂控制”快捷方式。它只打开控制面板，不会自动启动仿真或发送运动。
面板显示“已连接”后才允许控制；阶段 1 缺少轨迹控制器，不能用面板运动。

## 使用

- 实际角度：从 /joint_states 持续读取，显示度和弧度。
- 目标滑条：以度为单位设置目标，范围来自机器人 URDF 的关节限制。
- 默认拖动只改变目标，点击“执行目标”后才发送。
- 勾选“松开滑条自动执行”后，每次松开鼠标提交一条轨迹；不是每个鼠标移动事件都发送。
- “目标跟随当前”：把滑条重新同步到实际反馈，不发送运动。
- “回初始姿态”：执行 home 关节配置。
- “张开夹爪 / 完全闭合夹爪”：驱动夹爪关节到 0 / 模型关节上限；当前模型上限为 0.8 rad。这不是夹持力设置。原抓取流程的 0.48 rad 是抓方块时的目标角度，不是完全闭合角度；原抓取流程保持不变。
- “取消本面板运动”：只取消此面板发出的当前动作，不是硬件急停，也不取消其他程序的目标。
- 运动中锁定滑条和新目标按钮，仍可取消。轨迹完成后核对新鲜关节反馈与目标误差，避免把“请求接受”当作“已经到位”。

最短运动时间可设 2～20 秒；角度跨度很大时程序会延长轨迹时间。这里不是严格的最大速度控制器，也不提供碰撞避障。
关闭窗口时若仍在运动，面板先请求取消并等待结果；若控制器失联，先恢复仿真或停止该仿真实例，再处理面板。
已有 lab.sh 命令与面板共用 action.lock，避免同一时刻互相发送目标；绕过入口直接使用 ROS action 的其他程序不受此锁保护。

## 从代码学习

1. `build_ui()` 创建滑条、开关、按钮和反馈标签。
2. `model()` 从机器人描述解析每个关节的有效范围。
3. `feedback()` 保存实际关节状态。
4. `send()` 把界面中的度转换后的弧度目标组装成 JointTrajectoryPoint。
5. `accepted()` / `result()` 分别处理动作接受和完成。
6. `tick()` 每 50 毫秒处理一次 ROS 回调与界面刷新，不创建跨线程 Tk 操作。
7. `cancel()` 取消当前面板动作，`finish()` 释放互斥锁并显示结果。

## 已验证

- 新面板连接模型和关节反馈后不会自动运动。
- 手腕滑条松开触发 0.10 rad 变化，实际反馈通过检查。
- 取消本面板动作返回 canceled。
- 机械臂恢复测试前关节值，夹爪闭合与恢复均通过。
- 测试日志：工作空间 logs/panel-selftest.log。
